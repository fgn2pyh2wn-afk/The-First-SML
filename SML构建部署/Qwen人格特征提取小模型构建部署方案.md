# Parallax × Qwen：人格特征提取小模型构建与部署方案

> 适用范围：Parallax 的「捏脸 / 人格社区 / 人格蒸馏」模块。
> 当前基线：`PersonaDistill/` 用 DeepSeek/Gemini 等 API 大模型做零训练两步蒸馏（人格档案 → 分身系统提示词），不训练、依赖第三方、语料必须上云。
> 本方案：以 Qwen 小模型为基座，训练一个专门做「人格特征提取」的小模型，本地/低成本云端可部署，产出的结构化人格画像直接接入现有 `PGMSubagents` 的人格提示词体系。

---

## 0. 一页摘要

| 项目 | 内容 |
|---|---|
| 目标 | 输入用户授权文本（聊天记录/自述/问卷）→ 输出结构化人格画像 JSON → 生成可注入 Parallax 的人格卡 |
| 基座 | Qwen3-1.7B（主训）/ Qwen3-0.6B（端侧），Apache-2.0 可商用 |
| 训练 | LoRA/QLoRA 指令微调 + DPO，LLaMA-Factory / ms-swift / Unsloth |
| 数据 | 用户自评问卷 + 大模型蒸馏弱标签 + 现有 `synthesize_dialogs` 合成，起步 2k–5k 条 |
| 部署 | 云端 vLLM/GGUF（T4/L4）＋端侧 llama.cpp / MLX 混合路由 |
| 成本 | 训练 ≤100 元；单条推理 <0.01 元（云端）、0（端侧） |
| 周期 | 4–6 周可上线第一个可用版本 |

## 1. 背景与目标

### 1.1 现状

- Parallax 已有 16 型 MBTI 讨论工作流（`PGMSubagents` 的人格设定 + 重申机制 + `JudgeAgent` 投票收敛）。
- `PersonaDistill` 已实现零训练蒸馏：调用 DeepSeek 等 API 从用户文本里"提炼人格档案 → 写分身提示词"，并可用 `synthesize_dialogs` 合成同人格对话。
- 痛点：每次提取都走大模型 API（慢、成本随用量线性涨、语料必须出设备上云），且人格定义被 API 模型的"风格"牵着走，不可控、不可复现。

### 1.2 本方案目标

训练一个 **1B–3B 级 Qwen 小模型**，专职完成一件事——**人格特征提取（Persona Feature Extraction）**：

```
授权文本（聊天记录 / 自述 / 问卷答案）
   → Qwen 小模型
   → 人格画像 JSON（OCEAN 五因子 + 社交风格 + 价值观 + MBTI 参考 + 证据 + 置信度）
   → 人格卡系统提示词（与 PersonaPrompt.personaBlock 同构）
   → 注入 Parallax：捏脸 agent / 社区复刻 / 讨论席位
```

三个直接用途：

1. **捏脸**：用户在小程序里授权语料，几秒内得到自己的专属人格 agent，加入 16 人格讨论。
2. **社区复刻**：人格卡以 JSON 包形式公开，他人可一键调用、借鉴复刻。
3. **人格演化**：每轮新语料增量更新画像，形成"数字生命"的长期档案。

## 2. 基座选型：为什么是 Qwen

| 型号 | 参数量 | 中文能力 | 许可 | Q4 量化体积 | 适用 |
|---|---|---|---|---|---|
| Qwen3-0.6B | 0.6B | 强 | Apache-2.0 | ~0.5 GB | 手机端侧、超低延迟 |
| Qwen3-1.7B | 1.7B | 强 | Apache-2.0 | ~1.2 GB | **主训/云端主模型** |
| Qwen2.5-1.5B | 1.5B | 强 | Apache-2.0 | ~1.0 GB | 生态最成熟的替代 |
| Qwen3-4B | 3.8B | 很强 | Apache-2.0 | ~2.7 GB | 质量优先的云端备选 |

选 Qwen 的理由：

- **中文第一梯队**：本项目语料以中文网络对话为主，Qwen 中文语义与口语理解明显占优；
- **许可干净**：Apache-2.0，模型权重与派生模型均可商用，无社区复刻的合规隐患；
- **尺寸族完整**：0.6B→4B 同一血脉，云端训练的 LoRA 可迁移到端侧小一号推理；
- **生态成熟**：LLaMA-Factory / ms-swift / Unsloth 微调、llama.cpp / vLLM / ONNX 推理全部原生支持。

主训推荐 **Qwen3-1.7B**（质量/成本/延迟平衡点）；端侧放 **Qwen3-0.6B Q4**。

## 3. 任务定义：人格特征体系设计

### 3.1 特征维度（核心设计）

不局限 MBTI。MBTI 只作"参考标签"输出，主维度是**可测量、可比较、可演化**的：

**① OCEAN 五因子（各 1–5 分，带证据句）**

- 开放性 Openness：对新事物/新想法的接受度
- 尽责性 Conscientiousness：计划性、自律、交付可靠性
- 外向性 Extraversion：社交能量来源、表达欲
- 宜人性 Agreeableness：合作倾向、冲突中的妥协度
- 神经质 Neuroticism：情绪波动、压力敏感性

**② 社交风格四维**

- 沟通节奏：主动发起 / 被动回应；话多话少；回复长短
- 冲突应对：回避 / 对抗 / 协调（对应现有 `decisionImprint` 的取舍逻辑）
- 决策偏好：直觉快 / 分析慢；风险偏好；摇摆程度
- 表达习惯：句式特征、口头禅、幽默风格、高频话题

**③ 价值观与动机**：从语料归纳 3–5 个关键词（如"朋友不能背叛""效率优先"）。

**④ MBTI 参考**：输出 `mbti_guess` + 置信度，仅作社区展示用，不参与画像计算。

### 3.2 输出 JSON Schema（微调契约）

```json
{
  "persona_id": "u_8f2a",
  "summary": "一句话画像",
  "ocean": {
    "openness": 4.2, "conscientiousness": 2.8, "extraversion": 4.5,
    "agreeableness": 3.9, "neuroticism": 3.1,
    "evidence": ["晚上十二点写，状态拉满——计划性弱但抗压", "能出门见朋友就绝不在家待着——高外向"]
  },
  "social": {
    "initiative": "高", "conflict": "先安抚再讲理", "decision": "先感觉后列利弊",
    "expression": ["口头禅：真的会谢", "喜欢用夸张对比", "高频话题：游戏、朋友、聚餐"]
  },
  "values": ["朋友不能背叛", "家人优先", "说好的事要做到"],
  "mbti_guess": "ENFP",
  "mbti_confidence": 0.62,
  "confidence": 0.83,
  "evidence_count": 24,
  "updated_at": "2026-10-16T12:00:00Z"
}
```

### 3.3 人格卡生成（与现有体系对齐）

画像 JSON 经模板函数转成与 `PersonaPrompt.personaBlock` **同构**的人格卡：

```text
【人格设定：自定义 u_8f2a】
身份：ENFP「晚点交付的行动派」
核心特征：……（由 summary + values + social 拼装）
表达与沟通风格：……（由 expression 拼装）
盲点与自我提醒：……（由 OCEAN 极值 + 冲突应对反推）
团队定位：……（由社交风格映射到 16 席中的角色）
```

好处：复用现有 **重申机制（restateBlock）与阶段隔离（isolation）**，自定义人格与 16 型人格在同一套防漂移框架下运行。

## 4. 数据方案

### 4.1 数据来源与合规

| 来源 | 说明 | 合规动作 |
|---|---|---|
| 小程序授权导入 | 微信聊天记录（用户主动勾选导入）、自述文字 | 明示用途；仅提取画像；支持一键删除 |
| 人格问卷 | BFI-44 简版 / 自定义 20 题（现成 `sample_user_data.json` 结构） | 问卷即自报标签 |
| 捏脸草稿 | 用户在"捏脸"里自己写的设定 | 天然授权 |

预处理统一做：去 ID、去手机号/地址/学校名等 PII 脱敏 → `normalize_user_data`（现有函数）→ 分块（≤8k tokens）。

### 4.2 标注策略（弱监督为主）

1. **强标签**：用户问卷自报（OCEAN 得分 + 关键问题回答），与本人语料配对，约 30%。
2. **蒸馏弱标签**：用 Qwen-Max / DeepSeek-Flash 按 3.2 的 Schema 给无标签语料打参考标签（复用现有 `persona_distill.py` 的两步蒸馏输出改造），约 65%；人工抽检 5%，不达标的批次重标。
3. **数据增强**：`synthesize_dialogs` 按画像合成同人格对话，扩充极端人格样本（避免长尾人格欠拟合）。

### 4.3 数量目标与切分

- 起步 **2k–5k 条**（每条 = 语料 + 参考自评 + 目标 JSON），滚动扩充；
- 划分：训练 80% / 验证 10% / held-out 测试 10%（按"人"切分，防止同一人语料泄漏）；
- 测试集只留人工/问卷强标签样本，保证评估可信。

## 5. 训练方案

### 5.1 指令模板

```text
system: 你是人格特征提取专家。只依据给出的文本推断，禁止编造证据；
        只输出一个 JSON 对象，严格遵循给定 Schema；不确定的维度给低置信度。
user:   【用户语料】……（截断 8000 tokens）
        【用户自评参考】（可选）…… 
assistant: { ...3.2 的 JSON... }
```

### 5.2 方法与超参（Qwen3-1.7B）

| 阶段 | 方法 | 关键超参 |
|---|---|---|
| Stage 1 SFT | QLoRA（nf4）+ LoRA | r=16–32，alpha=2r，lr 2e-4，3 epochs，batch 8 × 梯度累计 4，warmup 5%，max_len 4096 |
| Stage 2 DPO | 偏好对：有证据/低幻觉 vs 空泛标签/贴 MBTI 标签 | beta=0.1，lr 5e-5，1 epoch |

框架任选：**LLaMA-Factory**（可视化、上手快）、**ms-swift**（中文社区活跃、支持 Qwen3 完整）、**Unsloth**（省显存、快 2 倍）。输出 JSON 稳定性用 `temperature=0.1` + schema 约束解码（outlines / XGrammar），解析失败重试一次再回退（与现有 `parseJSONObject` 思路一致）。

### 5.3 算力与成本

- 单卡 24GB（4090 / A10 / AutoDL 常见配置）即可 QLoRA 1.7B；
- 5k 条 × 3 epoch ≈ 6–10 GPU 时，AutoDL 4090 约 2 元/时 → **SFT 一轮约 20 元**，加 DPO 与调参总计 **<100 元**；
- 蒸馏打标 5k 条用 DeepSeek-Flash 约 10–20 元。

### 5.4 白盒蒸馏备选（质量上限更高）

若追求更高精度：用 Qwen-Max 对样本做 logits 蒸馏（输出层 KL 对齐 3.2 的 JSON 分布），替代纯 SFT 标签。成本高一个数量级，建议 v2 再上。

## 6. 评估方案

| 指标 | 定义 | 达标线 |
|---|---|---|
| OCEAN MAE | 五维与人工/问卷标签的平均绝对误差 | < 0.4 |
| 证据命中率 | 输出的 evidence 能定位到原文本的占比 | > 70% |
| 克隆自洽性 | 用人格卡扮演后重新提取的画像与原画像余弦相似度 | > 0.85 |
| 幻觉率 | 无文本依据的特征占比 | < 5% |

基线对比三条：问卷直接映射（规则）、现有 DeepSeek 蒸馏管线、微调小模型。目标：**小模型 ≥ 现有 API 管线效果，成本降低 90%+**。

## 7. 部署方案

### 7.1 云端（当前主选）

```text
小程序 ──► Parallax 云服务（Vapor / persona 路由）
              └─► /v1/persona/extract
                      └─► vLLM（OpenAI 兼容）Qwen3-1.7B AWQ/GGUF
                              ├─ T4/L4 单卡，批量并发 8–16
                              └─ 结果缓存 Redis，画像入库 PostgreSQL(jsonb)
```

- 推理延迟：1.7B Q4 单条约 1–2s（GPU），批处理摊薄后 <0.5s；
- 单条成本：<0.01 元（T4 约 1.2–2 元/时，高峰并发即可摊平）；
- 接口契约（与现有 `/v1/discussions` 风格一致）：

```json
POST /v1/persona/extract  { "texts": [...], "questionnaire": {...}, "privacy": "consented" }
GET  /v1/persona/{id}     → 画像 JSON + 人格卡提示词
```

- 兜底策略：小模型服务不可用时自动切回 API 大模型蒸馏管线，保证捏脸功能不断。

### 7.2 端侧（演进方向，隐私最强）

- **iPhone/Mac**：MLX 跑 Qwen3-0.6B Q4（Apple 芯片上 1s 内），或 ONNX Runtime；
- **Android/桌面**：llama.cpp + GGUF Q4_K_M（~0.5GB）；
- 语料不出设备，满足"人格蒸馏全程本地"卖点；模型随应用包/按需下载。

### 7.3 混合路由

| 场景 | 路由 |
|---|---|
| 语料 <2k 字、设备支持端侧 | 端侧推理 |
| 长语料 / 社区复刻 / 批量 | 云端 vLLM |
| 用户关闭云端授权 | 强制端侧（功能降级但可用） |

## 8. 与 Parallax 现有系统的集成点

1. **替换 PersonaDistill 的 distill 第一步**：`distill()` 的"人格档案生成"改调小模型服务，API 大模型保留为兜底；
2. **人格卡 → PGMSubagents**：新增 `PersonaPrompt.customBlock(profile:)`，输出与 16 型同构的人格设定块，自动获得重申与隔离机制；
3. **社区复刻**：人格卡标准化为带 schema 版本号的 JSON 包（含 `source: "qwen-extract-1.0"`），公开、评分、可复刻；
4. **JudgeAgent 联动**：画像的历史支持度可并入 `OptimizedParameters`，形成"这个人格在讨论中的影响力权重"；
5. **审计**：每次提取保存 `evidence` 溯源台账，与现有"证据可追溯"原则一致。

## 10. 风险与合规

- **隐私**：语料仅用于画像提取，默认脱敏 + 端侧优先 + 一键删除；公网传输加密。
- **伦理**：画像服务于"自我了解与娱乐"，不用于招聘、信贷等歧视性决策；不主动推断健康/取向等敏感属性，除非用户明示。
- **幻觉**：置信度 + 证据溯源 + 低置信即拒答；人格卡生成时剔除无证据特征。
- **许可**：Qwen 权重 Apache-2.0 可商用；用户语料需明示授权范围；社区公开人格卡需本人同意。
- **模型漂移**：人格卡接入讨论后仍走重申/隔离机制，防止扮演过程中人格漂移。
