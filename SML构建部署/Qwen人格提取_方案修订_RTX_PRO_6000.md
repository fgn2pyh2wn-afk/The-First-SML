# Qwen 人格提取 · 方案修订（云服务器 + NVIDIA RTX PRO 6000 Blackwell）

> 修订对象：《Qwen人格特征提取小模型构建部署方案.md》《Qwen人格提取模型_SFT_DPO_LoRA设计方案.md》。
> 结论先行：96GB 显存让三个关键决策全部升级——**QLoRA 4bit 改全参微调、1.7B 升 4B、蒸馏标签改为自托管 32B**。上一份设计里的算法/物理约束映射（字段加权 CE、熵正则、对比项、偏好对构造、能量极性）**全部保留不变**，只改资源相关参数与部署架构。

## 1. 硬件盘点（RTX PRO 6000 Blackwell）

| 项 | 规格 | 对本项目意味着什么 |
|---|---|---|
| 显存 | 96GB GDDR7 ECC | 4B 全参微调轻松；DPO 双模型同驻；标签大模型可同卡部署 |
| CUDA 核心 | 24,064 | 训练吞吐约为 4090 的 2.5–3 倍 |
| 带宽 | ~1.79 TB/s | 长序列（8k）前向/反向不再瓶颈 |
| 算力 | FP32 125 TFLOPS、FP4 4 PFLOPS | bf16 训练即可；FP8 可选加速 |
| 计算能力 | sm_120（Blackwell） | **必须 CUDA ≥12.8（vLLM 建议 12.9+）、PyTorch ≥2.7** |
| 功耗 | 600W | 服务器电源建议 ≥1600W，供电头 12V-2x6；确认云厂商机箱散热 |
| 接口 | PCIe Gen5 x16 | 模型加载/数据搬运无忧 |

**Day 0 环境验收**（上机第一件事）：

```bash
nvidia-smi                                  # 确认 96GB、驱动 ≥ 570（CUDA 12.8）
nvcc --version                              # ≥ 12.8，不足则重装
python -c "import torch; print(torch.__version__, torch.cuda.get_device_capability())"
# 期望 torch ≥ 2.7.0，capability (12, 0)
pip show vllm                                # 建议 ≥ 1.x（支持 sm_120 B12X FP8 kernels）
```

若云厂商镜像还是 CUDA 12.4/12.6：直接换官方 PyTorch 12.8 镜像，不要打补丁硬跑（sm_120 是老 CUDA 不认识的架构）。

## 2. 三个关键决策变更（旧 → 新）

| 决策点 | 旧方案（消费卡假设） | 新方案（RTX PRO 6000） |
|---|---|---|
| 训练方式 | QLoRA 4bit（显存不够） | **Qwen3-4B 全参微调（首选）**；8B 用 bf16 LoRA（备选） |
| 基座尺寸 | 1.7B 主训 / 0.6B 端侧 | **4B 主训**；1.7B/0.6B 仍保留给端侧 |
| 序列长度 | 4096（截断 8k 语料） | **8192**，信息预算守恒的 8k 语料不再截断 |
| 标签蒸馏 | 调 DeepSeek/API 打标（付费+出网） | **Qwen3-32B-AWQ 自托管打标**（同卡部署，约 19GB） |
| 训练耗时/成本 | 8–12 GPU 时，~100 元 | **2–5 GPU 时**，租赁场景 30–50 元 |
| 推理部署 | T4 小卡跑 1.7B | **同卡 vLLM 跑 4B/8B + 32B 标签模型共存** |

## 3. 96GB 显存预算（分阶段算账）

### 3.1 Stage A：SFT 全参微调 Qwen3-4B（bf16 + 梯度检查点）

| 占用 | 估算 |
|---|---|
| 模型权重 bf16 | 8 GB |
| AdamW 状态 fp32（m, v） | 32 GB |
| 梯度（bf16） | 8 GB |
| 激活 + 8k 序列（梯度检查点开启） | 10–15 GB |
| 合计 | **~58–63 GB** |

富余 30GB+ 的意义：可以把 batch 从 8 提到 **16**（×GA2 有效 32），或干脆把序列拉到 8k 同时开 packing。**不需要 4bit 量化，避免量化噪声污染数值回归任务。**

### 3.2 Stage B：DPO（Qwen3-4B 全参）

| 占用 | 估算 |
|---|---|
| policy 权重 + optimizer | 8 + 32 GB |
| reference 权重（冻结，无优化器） | 8 GB |
| 激活/梯度检查点 | 12–18 GB |
| 合计 | **~60–66 GB** |

双模型同驻没有压力；`β` 退火与偏好对构造沿用原设计（§4.1/4.2）。

### 3.3 Stage C：推理共存（vLLM，单卡跑三个服务）

| 常驻模型 | 量化 | 显存 |
|---|---|---|
| persona-extract 主力：Qwen3-4B | AWQ 4bit / FP8 | 4–5 GB |
| 标签蒸馏/兜底：Qwen3-32B | AWQ 4bit | ~19 GB |
| KV cache 池 + 并发批 | — | 预留 24–32 GB |
| 合计 | | **~50 GB，富余 40GB+** |

结论：**同一张卡白天推理、晚上训练**都成立；训练与推理不建议同时跑（抢带宽），切换用不同 vLLM 实例 + 权重热加载。

## 4. 修订后的训练配置

> 未列出的组件（字段加权 CE、熵正则 0.35 nats、对比项 γ=0.05、Frobenius 惩罚、标签平滑 0.1、样本价值截断 [0.5v̄, 2v̄]）**完全沿用上一份设计**。

### 4.1 SFT（首选：Qwen3-4B 全参）

| 超参 | 新值 | 说明 |
|---|---|---|
| precision | bf16 | 不用 4bit |
| seq len | 8192 | 完整保留 8k 语料（信息预算守恒） |
| batch | 16 × GA 2（有效 32） | 96GB 支撑 |
| lr | **1e-5**（峰值，cosine） | 全参微调比 LoRA 低一个量级 |
| epochs | 3 | 数据少，防过拟合 |
| warmup | 5% | — |
| optimizer | AdamW β=(0.9, 0.95)，wd 0.05 | — |
| grad clip | 1.0 | 对应"单轮变动 ≤20%" |
| gradient checkpointing | 开 | 显存换 20% 时间，划算 |
| 早停 | val MAE 连续 2 轮不降 | 对应 H3 |
| 预计时长 | 2–5 GPU 时 | 5k 样本量级 |

### 4.2 SFT 备选（Qwen3-8B，bf16 LoRA）

若 4B 评估不达标再上 8B：`lora_rank: attn=32 / mlp=64`，`rsLoRA α/√r`，`lr 2e-4`，其余同 4.1。显存约 40–50GB。

### 4.3 DPO（Qwen3-4B 全参）

| 超参 | 新值 |
|---|---|
| lr | 5e-6（峰值） |
| β 退火 | 0.5 → 0.35 → 0.1 |
| batch | 4 × GA 4 |
| 长度正则 | 保留 |
| reference | 冻结 SFT ckpt，同驻显存 |

### 4.4 标签蒸馏自托管（替代 API 打标）

```bash
# 下载 32B AWQ 一次（~19GB），之后全部本地生成弱标签
vllm serve Qwen/Qwen3-32B-AWQ --dtype auto --max-model-len 8192 \
  --gpu-memory-utilization 0.25   # 与训练/其他服务共存时的水位
```

收益：标签数据不出服务器（隐私口径更硬）、打标成本归零、晚上闲时批量跑。

## 5. 部署架构修订（单卡全流程）

```text
                    ┌─────────────────────────────────────────────┐
                    │  云服务器（RTX PRO 6000, 96GB）              │
                    │                                             │
  Parallax 云服务 ──► vLLM :8001  Qwen3-4B-AWQ   persona-extract  │
  (Vapor + Redis)    │  vLLM :8002  Qwen3-32B-AWQ  标签/兜底(夜)   │
                    │  [训练窗口] ms-swift SFT/DPO 全参(独占GPU)   │
                    └─────────────────────────────────────────────┘
```

- 上线初期：`:8001` 常驻 4B 提取服务，KV 池 24GB，并发 16–32；
- 夜间窗口：停掉 :8002 打标服务，GPU 全量给训练；训练期间提取服务可切 CPU 版 1.7B（GGUF）降级；
- 讨论引擎（16 人格 Gemini/DeepSeek API）**不迁移**到本卡：32B 并发跑 16 人格吞吐不够，成本也不如 API 小模型。本卡专职"人格提取 + 标签"。

## 7. Blackwell 专属风险清单

1. **CUDA/驱动版本**：sm_120 需要 CUDA 12.8+（vLLM 建议 12.9+）、PyTorch 2.7+。镜像不对就先换镜像，别硬跑。
2. **vLLM 单卡无坑**：custom all-reduce 的 sm_120 问题只影响多卡；本项目单卡，不受影响。
3. **供电散热**：600W TDP，确认云厂商电源 ≥1600W 与 12V-2x6 供电；机箱风道正常再长训。
4. **FP8 是选修**：Blackwell FP8 训练更快，但生态仍在成熟，先用 bf16 保底，验收后再试 FP8。
5. **磁盘**：模型 4B 8GB + 32B AWQ 19GB + 数据集 + ckpt，SSD ≥1TB。
6. **数据合规**：自托管打标后，用户语料全程不离开服务器，可写入隐私说明（对小程序审核和比赛答辩都是加分项）。
